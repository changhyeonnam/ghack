# LedgerLens synthetic demo dataset

Three fictional micro-business loan applications with 20 planted underwriting traps and a
machine-readable answer key. Built for the AI Builder Cup 2026 (BFSI) LedgerLens demo and benchmark.

**Everything in this directory is synthetic.** There is no real customer, merchant, bank or
platform data. Bank names are invented and suffixed "(synthetic)"; account numbers are masked
placeholders; people, shops and amounts are generated by `generate.py` from a fixed random seed.
Every rendered page and image carries a visible `SYNTHETIC · FOR DEMO` watermark. Brand-like words
that appear in document text (e.g. a marketplace or courier name on a receipt) are there only to make
the documents look like what an underwriter would really receive; they do not come from those companies.

## Layout

```
data/synth/
  SPEC.md                 specification this generator implements
  traps.json              answer key: 20 traps (id, type, case, description, match rules)
  generate.py             entry point  -> python generate.py --seed 7 --out cases
  verify.py               re-reads ground truth and asserts every trap effect / invariant
  profiles.py             case profiles, fonts, formatting, photo-effect helpers
  gen_bank.py             transaction simulation + ReportLab statement renderer (records bboxes)
  gen_dashboard.py        Shopee-like seller centre captures (PIL) + monthly sales plan
  gen_receipts.py         thermal / handwritten supplier receipts, GHN / J&T logistics receipts
  gen_ledger.py           handwritten ledger pages (Filipino headers)
  gen_premises.py         stylised premises illustrations
  cases/
    index.json
    A/  manifest.json  docs/  ground_truth/{bank_statement,receipts}.json
    B/  manifest.json  docs/  ground_truth/{bank_statement,dashboards,receipts}.json
    C/  manifest.json  docs/  ground_truth/{bank_statement,ledger}.json
  past_cases/
    index.json                     [{case_id, filename, sha256, phash}]
    PAST-2025-0471/premises.jpg    prior applicant photo reused in case C (trap T20)
```

`docs/` is exactly what gets uploaded to LedgerLens. `ground_truth/` is the benchmark / mock-mode
answer key: every bank row, dashboard KPI, receipt total and ledger entry with a normalized
`[ymin, xmin, ymax, xmax]` bbox (0–1000 of the page/image) and the `trap_ids` it participates in.

## Regenerating

```bash
cd data/synth
../../backend/.venv/bin/python generate.py --seed 7 --out cases   # ~5 s, ~8 MB
../../backend/.venv/bin/python verify.py                          # prints a PASS/FAIL table, exit code 0 on success
```

Dependencies: Python 3.12 with `reportlab`, `pillow`, `numpy`, `imagehash`, `pymupdf` (all in the backend venv).
Fonts are loaded from `/System/Library/Fonts{,/Supplemental}` (macOS); missing fonts fall back to Arial / PIL default.
Output is deterministic for a given seed (PDFs are written with ReportLab's `invariant` mode; all randomness
comes from seeded `random.Random` / `numpy` generators). `--imagen` is reserved for optional Gemini image
generation of premises photos and is currently a no-op.

## Ground-truth conventions

- Dates are ISO (`2026-02-17`) in JSON; on the documents they use the local format
  (`17/02/2026` for ID/VN, `02/17/2026` for PH, as stated in the PH statement footer).
- Amounts are plain numbers in JSON; on the documents they use local formatting
  (`18.500.000` for IDR/VND, `14,800.00` for PHP).
- `bbox` = `[ymin, xmin, ymax, xmax]` normalized to 0–1000 of the rendered page (PDF) or image
  (PNG/JPG), top-left origin. For statements every transaction row plus opening/closing balance rows
  carry a bbox; `verify.py` confirms with PyMuPDF that the balance text of every row is found inside it.
- Balances are continuous (`prev + credit − debit == balance_after`) everywhere except the planted
  breaks T11, T12 (case B) and T16 (case C), which are also listed under `balance_breaks`.
- Case A receipts flagged `paid_by_bank_transfer` have a matching `TRF KE <merchant>` debit on the same
  date for evidence linking; the others are cash purchases.

## What `verify.py` asserts

File counts and PDF page counts match the manifests; every `trap_ids` reference exists in `traps.json`
and belongs to the right case; balance continuity (with exactly the planted exceptions); all 20 trap effects
with their exact amounts; duplicate images phash-match (distance ≤ 4) without being byte-identical (T08, T15)
or being byte-identical (T20); watermark text on every PDF page; row/KPI/ledger bboxes within range;
total size under 25 MB.
